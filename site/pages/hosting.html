Get started

Setup & publish

You need both: a public app link {{help public-link}} that anyone can open, and a public GitHub repository {{help github-backup}}, which is also what you submit. Publish the untouched starter first, in step 3.

Choose Streamlit or Node.js

The starter has the same four plain sections twice. Pick the one you'd rather build in, and build and host only that one. Both earn the same credit. Either way, your Python analysis runs on your computer, and the hosted app only reads the files it exported to results/.

If you like, delete the app you don't use (streamlit_app.py, or web/, index.html, .nojekyll and package.json). Keep m11.py: the analysis and check.py use it.

1. Set up with your agent

You need git, uv, a Bash terminal (on Windows: Git Bash or WSL) and an AI coding agent, plus Node.js 20 or newer if you chose Node.

  1. Download and unzip the starter from Data & files.
  2. Open the starter folder in your agent and give it this starting prompt, with your app choice filled in: 
    Read AGENT_BRIEF.md and follow it for this whole project. I chose the <Streamlit or Node.js> app.
Inspect the starter (README.md, SETUP.md, analysis/, m11.py, check.py and my app's files) and summarise it in a few sentences.
Then help me set up the environment: create the uv virtual environment from requirements.txt and run python check.py --stage setup.
Explain each command before you run it, and what its output means.
  3. Read the check's output yourself: every line should say ok.
  4. On GitHub, create a new public repository (for example judge-the-model). Don't add a README; the starter has one.
  5. In the starter folder, run: 
    git init -b main
git add .
git commit -m "Starter"
git remote add origin https://github.com/<username>/<repo>.git
git push -u origin main

2. Launch it on your computer

Ask your agent

Write run_app.sh, a Bash script that starts my app on this computer, as AGENT_BRIEF.md describes. Then tell me where to run it, what it needs, the exact command, the address to open, and how to stop it. Don't run it for me.

  • Run it yourself in a terminal in the starter folder: bash run_app.sh. Open the address it prints; stop it with Ctrl+C.
  • Windows: use Git Bash or WSL. PowerShell and Command Prompt can't run Bash scripts.
  • This runs the app only on your computer, so you can check your work. Publishing (next step) is what gives you a public link.
  • Commit and push run_app.sh: check.py looks for it.

3. Publish the untouched starter

Streamlit: Streamlit Community Cloud

  1. Go to share.streamlit.io and sign in with GitHub.
  2. Click Create app, then pick your repository, branch main and file streamlit_app.py.
  3. Click Deploy. It installs the pinned packages in requirements.txt; list any package you add there too.

Node.js: GitHub Pages

  1. On your repository's GitHub page, open Settings, then Pages.
  2. Under Build and deployment, set Source Deploy from a branch, Branch main and folder / (root), then click Save.
  3. After a minute or two your link appears at the top of that page: https://<username>.github.io/<repo>/. The starter's top-level index.html sends visitors on to the app in web/.

GitHub Pages serves your files as they are, with no npm and no server code: run_app.sh is only for your computer. If you add a library, save its browser module in web/ or load it from a CDN.

4. Test it in a private window

  • Open your link in a private or incognito window. It must load without signing in and show the starter's baseline-only results.
  • Check every section and model later, once your app is built: see the submission checklist.
  • Put your link on the first line of README.md, then commit and push.

5. Push updates

Commit and push whenever a section starts working, after each run of the analysis, and after your final checks. Commit results/ too: your hosted app reads it from GitHub.

git add .
git commit -m "Section 2 works"
git push

Your host updates a minute or two after you push. A commit on your laptop is not a backup until it's pushed. Never commit passwords, tokens or API keys.

Troubleshooting

bash run_app.sh fails

Read the first error line and give it to your agent. On Windows, run it in Git Bash or WSL. “bad interpreter” or \r errors mean Windows line endings: ask your agent to save the script with LF line endings.

The app says there are no results
  • Check that results/ is committed and pushed: open your repository on GitHub and look for results/diabetes.json.
  • Streamlit: load results through m11.load(...), which finds results/ next to m11.py.
  • Node: fetch ../results/<name>.json the way the starter's load() in web/app.js does. A path starting with / breaks on GitHub Pages, because your app lives under /<repo>/. On your computer, start the app with bash run_app.sh.
The Streamlit app is asleep

Apps on Streamlit Community Cloud sleep after a few days without visitors. Open the link and click the button to wake it. Open it again just before you submit.

Streamlit says "ModuleNotFoundError"

Add the missing package to requirements.txt with a pinned version, commit and push. Streamlit redeploys automatically.

The GitHub Pages link shows a 404 or old numbers
  • Check that the repository is public and that Settings → Pages uses branch main and folder / (root). The first publish can take a few minutes; the Actions tab shows its progress.
  • Pages updates a minute or two after each push. If you still see old numbers, reload with Ctrl+Shift+R (Mac: Cmd+Shift+R).
The Node app shows a blank page or no numbers

Open the browser's developer console (F12) and read the first error: it names the file and line in web/. A 404 for a file means it isn't committed, or its path starts with /.

import lightgbm fails on a Mac

If the message mentions libomp, run brew install libomp, then try again.

Nothing works

Run the app on your computer with bash run_app.sh, and give the first error to your agent. Tell your instructor if your link breaks after you submit.
