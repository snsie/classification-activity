Publish & back up

You need both: a public app link {{help public-link}} that anyone can open, and a public GitHub repository {{help github-backup}}. Publish the untouched starter first, in step 1. It takes about 20 minutes.

Both are required

A repository alone isn't a hosted app, and a hosted app alone isn't a backup. Your repository is also what you submit, and its git history shows that you saved each decision before each stage.

Either way, your Python analysis runs on your computer, and the app only reads the files it exported.

2. Put the starter on GitHub

  1. Download and unzip the starter from Data & files.
  2. Install Python 3.11 or newer and git. In the starter folder, run: 
    python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python check.py --stage setup
  3. On GitHub, create a new public repository (for example judge-the-model). Don't add a README; the starter has one.
  4. In the starter folder, run: 
    git init -b main
git add .
git commit -m "Starter"
git remote add origin https://github.com/<username>/<repo>.git
git push -u origin main

    You need git on your computer, not only the GitHub website: the workflow checks your commits before it trains or tests.

3. Publish the untouched starter

Route A: GitHub Pages (recommended)
  1. On your repository, open Settings → Pages.
  2. Under Source, choose Deploy from a branch, then branch main and folder / (root). Click Save.
  3. After 1–2 minutes your link is https://<username>.github.io/<repo>/. It opens app/.

To try it on your computer first, run npm run serve (or python -m http.server 8000) and open http://localhost:8000/app/. Opening the HTML file directly won't load the results.

Built with Node (for example Vite)? That's fine. Deploy the built output to GitHub Pages (for example with a GitHub Actions workflow), and make sure the built site still contains results/ at the path your code loads it from.

Route B: Streamlit Community Cloud
  1. Go to share.streamlit.io and sign in with GitHub.
  2. Click Create app, then pick your repository, branch main and file streamlit_app.py.
  3. Click Deploy. It installs the pinned packages in requirements.txt; list any package you add there too.

To try it on your computer first: streamlit run streamlit_app.py

4. Test it in a private window

  • Open your link in a private or incognito window. It must load without signing in.
  • Switch datasets and models in every section.
  • Put your link on the first line of README.md, then commit and push.

5. Push updates

Commit and push whenever a section starts working, after each workflow stage, and after your final checks. Commit results/ too: your hosted app reads it from GitHub.

git add .
git commit -m "Section 2 works"
git push

Both hosts update a minute or two after you push. A commit on your laptop is not a backup until it's pushed. Never commit passwords, tokens or API keys.

Troubleshooting

The page is blank, or says there are no results
  • Check that results/ is committed and pushed: open https://<username>.github.io/<repo>/results/heart_dev.json. It should show data.
  • Load results through m11.load(...), which finds results/ from app/m11.js. Don't use a leading slash in your own paths.
  • Open the browser's developer console (F12) and read the first error. Before you run the test, “404” lines for *_test.json and test_record.json are expected: those files don't exist yet.
  • Hard-refresh (Ctrl+Shift+R, or Cmd+Shift+R on a Mac); browsers can cache old files.
My GitHub Pages link shows "404"

Wait two minutes. Check that Pages is set to branch main, folder / (root), and that index.html and app/ are at the top of the repository, not inside another folder.

The Streamlit app is asleep

Apps on Streamlit Community Cloud sleep after a few days without visitors. Open the link and click the button to wake it; it takes about a minute. Open it again just before you submit.

Streamlit says "ModuleNotFoundError"

Add the missing package to requirements.txt with a pinned version, commit and push. Streamlit redeploys automatically.

import lightgbm fails on a Mac

If the message mentions libomp, run brew install libomp, then try again.

Nothing works

Switch to the other route. Both read the same results/ files with the same helpers, so your analysis carries over. Tell your instructor if your link breaks after you submit.
