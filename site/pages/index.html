M11 take-home activity

Judge the Model

Run a supplied Python workflow that trains four classifiers plus a baseline on two health datasets and evaluates them on a test set. Then build one app, in Streamlit or Node.js, that helps a clinical lead {{help clinical-lead}} decide whether any model is fit for each job.

Which classifier would you trust for this job, at what threshold, and with what limits?

Start here

  1. Set up
    • Download the starter, create a public GitHub repository {{help github-backup}}, use uv to create a virtual environment with the requirements, and run python check.py --stage setup.
    • Choose Streamlit or Node.js and publish the untouched starter. It shows baseline-only results.
    Done when: the check passes and your app link loads in a private window.
  2. Decide what matters
    • Read both dataset scenarios: 30-day readmission and diabetes screening.
    • Then, before you look at any results, fill in Before results in DECISIONS.md {{help decisions-md}}: the positive class for each job, and which error matters more. Commit and push.
    Done when: the commit is on GitHub.
  3. Write the kNN pipeline and run the analysis
    • Complete the kNN TODO in analysis/models.py, following the logistic regression example. Models
    • Run python -m analysis. Analysis
    Done when: python check.py --stage results passes. Commit and push results/.
  4. Build your app
    • Build the four sections to their required minimums for a clinical lead.
    • Commit and push, then test in a private window.
    Done when: every section works for both datasets and the four classifiers plus a baseline.
  5. Write your recommendations
    • Fill in Recommendations in DECISIONS.md: for each job, a model and threshold, or “none is adequate”, with a reason.
    • Fill in Design choice and AI use: one thing you chose to show or leave out for your clinical lead, and one AI suggestion you turned down.
    • Run python -m analysis again so your app shows them, then commit and push.
    Done when: python check.py passes.
  6. Answer the Canvas questions
    • Five answers of 100–150 words each, citing numbers from your app. The questions are on Canvas.
    • Submit your repository link.

How your work is judged

Most of the credit is for reasoning: 45 points for your five Canvas answers, each using your own numbers, tied to the job and stating the uncertainty. Your app earns 25 for meeting the four required minimums in a way a clinical lead can read cold, and 5 more for one design choice of your own, explained in DECISIONS.md. A valid analysis earns 15, and your decisions 10. You get no points for a higher AUROC, for choosing a particular model or for visual polish: a plain app with a well-reasoned design choice earns full credit. After the deadline, every app goes into a class gallery. Full rubric

Fair play

The protocol

  • Use the supplied split. Never reshuffle, and never fit a model on test rows. {{help five-rules}}
  • Keep preprocessing inside the pipeline, so it learns from the training rows only.
  • Never edit results by hand. Your app computes every number from results/ through m11.

AI use

  • You may use an AI agent to write app code, debug, explain the starter, and help with the kNN pipeline.
  • You make every decision in DECISIONS.md yourself, and you write your Canvas answers in your own words.
  • Check what the agent gives you. When you submit, say which AI tools you used, or “none”.
  • Ask your agent for options, not answers. In DECISIONS.md you record one AI suggestion you turned down, and your design choice must be your own idea.
  • Follow the course AI policy for anything not covered here.
  • Optional and ungraded: save your prompts in prompts/, one file per session.

Have your agent read AGENT_BRIEF.md first. It holds the rules that keep the analysis fair and the numbers right.
