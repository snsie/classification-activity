M11 take-home activity

Judge the Model

Run a supplied Python workflow that trains five classifiers on three health datasets. Save each decision before you see the results it depends on. Then build one app that helps a clinical lead {{help clinical-lead}} decide whether any model is fit for each job.

Which classifier would you trust for this job, at what threshold, and with what limits?

How your work is judged

Most of the credit is for reasoning: 40 points for your four Canvas answers, each using your own numbers, tied to the job and stating the uncertainty. Your app earns 20 for meeting the four required minimums in a way a clinical lead can read cold. A valid, reproducible analysis earns 15, your decisions and verification 15, and the diabetes threshold 10. You get no points for a higher AUROC, for choosing a particular model, for visual polish, or for a correct prediction before results. Full rubric

Start here

  1. Set up (~20 min)
    • Download the starter, create a public GitHub repository {{help github-backup}}, install the requirements, and run python check.py --stage setup.
    • Publish the untouched starter app on your chosen route and open it in a private window.
    Done when: the check passes and your app link loads.
  2. Decide before results (~15 min)
    • Fill in Before results in DECISIONS.md {{help decisions-md}}. Commit and push.
    Done when: the commit is on GitHub.
  3. Write two pipelines and train (~30 min)
    • Complete the kNN and SVM TODOs in analysis/models.py, following the logistic regression example. Models
    • Run python -m analysis train.
    Done when: python check.py --stage train passes.
  4. Choose the diabetes model (~20 min)
    • Run python -m analysis explore, or use your app's Section 2.
    • Choose a model. It doesn't have to have the highest specificity. If models are close, or one is better calibrated, you may prefer it.
    • Fill in Before test. Commit and push.
    Done when: the commit is on GitHub.
  5. Run the test once and record (~15 min)
    • Run python -m analysis test once. Don't change any decision afterwards; explain surprises in Canvas.
    • Fill in Verification and Recommendations, then run python -m analysis export.
    Done when: python check.py passes.
  6. Build your app (~90 min)
    • Build the four sections to their required minimums for a clinical lead.
    • Commit and push, then test in a private window.
    Done when: every section works for every dataset and model.
  7. Answer the Canvas questions (~60 min)
    • Four answers of 100–150 words each, citing numbers from your app. The questions
    • Submit your repository link.

Fair play

The protocol

  • Use the supplied folds. Never reshuffle, and never fit on test rows. {{help five-rules}}
  • Decide first. Commit each section of DECISIONS.md before the stage that depends on it. The workflow refuses to run until you do, and check.py reads the git history.
  • Open the test set once. {{help test-set}} Don't change any decision afterwards. A forced second run is logged.
  • Never edit results by hand. Your app computes every number from results/ through m11.

AI use

  • You may use an AI agent to write app code, debug, explain the starter, and help with the two pipelines.
  • You make every decision in DECISIONS.md yourself, and you write your Canvas answers in your own words.
  • Check what the agent gives you, and report one check under Verification.
  • Follow the course AI policy for anything not covered here.
  • Optional and ungraded: save your prompts in prompts/, one file per session.

Have your agent read AGENT_BRIEF.md first. It holds the rules that keep the analysis fair and the numbers right.
