The work

Models

Five classifiers plus a baseline, all fixed. Everyone compares the same models with the same settings: you don't tune anything. Logistic regression, random forest and gradient boosting are from the lecture (§11–12). kNN and SVM are new, and you write their pipelines {{help pipeline}}.

Every pipeline starts with the supplied encode() step, which turns each text category into 0/1 columns, learned from the training rows only. “Impute” fills each missing value with the training median {{help imputation}}; “scale” puts every feature on the same scale {{help scaling}}.

Simplicity order, used by the §16 rule {{help within-one-sd}}: logreg < kNN < SVM < random forest < gradient boosting.

Write your two pipelines

Open analysis/models.py. Copy the shape of logreg():

def logreg():
    return make_pipeline(
        encode(),                              # 1. text categories → 0/1 columns
        SimpleImputer(strategy="median"),      # 2. fill missing values with the training median
        StandardScaler(),                      # 3. put every feature on the same scale
        LogisticRegression(max_iter=5000),     # 4. the classifier
    )
  • kNN: the same four steps, ending in KNeighborsClassifier(n_neighbors=25).
  • SVM: the same four steps, ending in LinearSVC(). Pass the whole pipeline to with_probabilities(...) and return that.
  • Keep scaling inside the pipeline. Never scale the whole dataset first: the scaler would learn from rows each fold should never see. python check.py --stage train checks this.

The six models

Supplied

Prevalence baseline {{help prevalence-baseline}}

Core idea: every patient gets the same probability: the share of positives in the training rows.

Limitation: it ranks no one above anyone else, so its AUROC is 0.5. It is the yardstick, not a model to use.

Supplied · worked example · lecture §12

Logistic regression {{help logistic-regression}}

Core idea: a weighted sum of the features, squeezed into a probability between 0 and 1 by an S-shaped curve.

Limitation: it misses curved or combined effects unless you add them as features.

New · you write the pipeline

k-nearest neighbours (kNN) {{help knn}}

Core idea: a new patient's probability is the share of positives among the k most similar training patients. Here k = 25.

Why scaling matters
“Similar” means close in distance across all features. A feature measured in large units (length of stay in days, lab counts in the dozens) would swamp one measured in small units (a 0/1 flag). Scaling puts every feature on the same footing, so each one counts.
The effect of k
A small k follows individual training patients closely, so its probabilities jump around. A large k averages more patients, so its probabilities are smoother but blur real differences. With k = 25, every probability is a multiple of 1/25 = 0.04.
Try it: drag a new patient and watch its neighbours

Limitation: it memorises the training patients rather than learning a formula, so it must search them all for every prediction, and it is easily misled by features that don't matter.

New · you write the pipeline

Support vector machine (SVM) {{help svm}}

Core idea: draw the straight boundary that separates the two classes with the widest possible gap. A few training patients right at the edge of the gap, the support vectors, fix where it goes.

The separating boundary
Patients on one side are scored as more likely positive, on the other side less likely. LinearSVC draws a straight boundary (a flat one, with more than two features), like logistic regression, but chooses it by the gap rather than by probabilities.
Its raw score is not a probability
An SVM outputs a raw score {{help raw-score}}: how far a patient is from the boundary, and on which side. Higher means more likely positive, but you can't read it as a chance. The supplied with_probabilities() helper converts it into a probability, so your SVM can be compared with the others.
Try it: a boundary on two features

Limitation: a straight boundary misses curved patterns, and the converted probability is only as good as the helper's conversion: check it with a calibration plot {{help calibration-plot}}.

Supplied · lecture §11

Random forest {{help random-forest}}

Core idea: many decision trees, each grown on a different sample of patients; the probability is the average of the trees' probabilities.

Limitation: it nearly memorises its training patients (training AUROC close to 1), and one prediction is hard to explain.

Supplied · lecture §11

Gradient boosting {{help gradient-boosting}}

Core idea: trees added in sequence, each one fixing the errors the earlier trees left.

Limitation: with many trees it can fit noise in the training patients; it has several settings, all left at LightGBM's defaults here.

Common questions

Why can't I tune k, or the SVM's settings?

Everyone compares the same fixed models, so differences come from the data and the comparison, not from tuning effort. Tuning is outside this activity.

Do I need to know how with_probabilities() works?

No. It turns the SVM's raw score into a probability between 0 and 1, learned from the training rows only. Check the result in Section 3 like any other model's probabilities.

My pipeline runs, but check.py says scaling isn't inside it.

Return one make_pipeline(...) with encode(), SimpleImputer and StandardScaler as steps before the classifier. Don't transform X yourself before training.
